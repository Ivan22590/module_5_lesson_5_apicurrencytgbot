# 💼 Мини-кошелёк путешественника

Telegram-бот, который помогает отслеживать расходы во время поездки **в двух валютах одновременно** — домашней и валюте страны назначения.

Курсы берутся из [api.exchangerate.host](https://api.exchangerate.host) и кешируются на 1 час, чтобы не превышать лимиты API. При недоступности сервиса бот использует последний известный курс.

## ✨ Возможности

- **Создание путешествия** (FSM-сценарий): страна отправления → страна назначения → подтверждение курса (или ручной ввод) → стартовая сумма
- **Учёт расходов**: отправьте любое число — бот конвертирует его, предложит выбрать категорию и подтвердит запись
- **Баланс**: остаток и потраченное в обеих валютах
- **Переключение путешествий**: несколько поездок, активная помечена 🟢
- **История расходов** с пагинацией по 5 записей
- **Ручное изменение курса** (`/setrate`), если API-курс не подходит

## 🛠 Стек

| Компонент | Технология |
|---|---|
| Язык | Python 3.11+ (type hints, PEP 484) |
| Бот | pyTelegramBotAPI (telebot) |
| Курсы | https://api.exchangerate.host |
| БД | SQLite через `sqlite3` (без ORM) |
| Конфигурация | `.env` + python-dotenv |
| Кеш курсов | in-memory `cachetools.TTLCache`, TTL 1 час |
| Логи | `logging` → `bot.log` (INFO+) и `bot_errors.log` (ERROR+ с трейсбеками) |
| Разметка сообщений | HTML |

## 🚀 Установка и запуск

### 1. Виртуальное окружение и зависимости

```bash
python -m venv .venv
.venv\Scripts\activate        # Windows
# source .venv/bin/activate   # macOS/Linux

pip install -r requirements.txt
```

### 2. Переменные окружения

Скопируйте шаблон и заполните значения:

```bash
cp .env.example .env
```

| Переменная | Описание |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен бота от [@BotFather](https://t.me/BotFather) |
| `CURRENCY_API_KEY` | API-ключ [api.exchangerate.host](https://api.exchangerate.host) |

Без этих переменных бот **не стартует** и печатает понятную ошибку.

### 3. Запуск

```bash
python main.py
```

База данных (`wallet.db`) и таблицы создаются автоматически при первом запуске.

## 📖 Команды

### Главное меню (Reply-кнопки)

| Кнопка | Команда-дубликат | Что делает |
|---|---|---|
| 🆕 Создать путешествие | `/newtrip` | FSM-сценарий создания поездки |
| 📂 Мои путешествия | `/switch` | список поездок, переключение |
| 💰 Баланс | `/balance` | остаток в обеих валютах |
| 📊 История расходов | `/history` | история с пагинацией |
| ⚙️ Изменить курс | `/setrate` | ручной ввод курса |

`/start` — регистрация и главное меню.

### Учёт расхода

В **главном меню** отправьте любое число (например `150`) — это трата в валюте страны назначения. Бот предложит выбрать категорию и подтвердит запись:

```
💸 Потрачено: 150 CNY ≈ 1 920 ₽
Выберите категорию расхода: [🍽 Еда] [🏨 Проживание] [🚕 Транспорт] ...

150 CNY = 1 920 ₽
🍽 Категория: Еда
[✅ Учесть расход] [❌ Отмена]
```

## 📋 Примеры сценариев

**Сценарий 1: Россия → Италия**

1. `/newtrip` → страна отправления «Россия» (RUB) → страна назначения «Италия» (EUR)
2. Бот: `Курс: 1 EUR = 104 RUB. Подтвердить?` → ✅
3. Стартовая сумма: `200000` → `✅ Путешествие «Италия 2026» создано! Баланс: 200 000 ₽ ≈ 1 923 €`
4. Отправляем `50` → категория «Еда» → подтверждаем
5. `✅ Учтено: 🍽 50 € (≈ 5 200 ₽)` → `Остаток: 1 873 € ≈ 194 800 ₽`

**Сценарий 2: Россия → Китай**

1. `/newtrip` → «Россия» → «Китай» (CNY)
2. Бот получает курс из API (или вы вводите его вручную, нажав ❌)
3. Стартовая сумма `1000` ₽ конвертируется в CNY по актуальному курсу
4. Каждое число = трата в юанях, бот показывает пересчёт в рубли

## ⚠️ Обработка ошибок

- Не число вместо суммы → «Пожалуйста, отправьте число»
- Неизвестная страна → «Не удалось определить валюту для этой страны. Проверьте название»
- API недоступен / лимит → «Сервис курсов временно недоступен, попробуйте позже» (используется кешированный курс, если есть; иначе предлагается ручной ввод)
- Нет активного путешествия → подсказка создать или выбрать
- Любое необработанное исключение логируется с трейсбеком в `bot_errors.log`, пользователь получает дружелюбное сообщение

## 🔍 Логирование

Ведутся два файла:

| Файл | Что попадает |
| --- | --- |
| `bot.log` | Все INFO+ события: входящие сообщения и callback-запросы, ответы бота, действия с БД и курсами |
| `bot_errors.log` | Только ERROR+ с полным трейсбеком |

Каждый обмен с пользователем подписывается — по логу видно, на каком шаге оборвался диалог:

```
ВХОД | message | user=341923031 (@Ivan2259026) | state=trip_to | text='Грузия'
ОТВЕТ send_message | chat=341923031 text='Курс: 1 GEL = 32.87 RUB Подтвердить?'
ВХОД | callback | user=341923031 (@Ivan2259026) | state=trip_rate_confirm | data='rate:yes'
ОТВЕТ answer_callback_query | callback_query_id=1468548240081334683
Создано путешествие id=1 user=341923031 «Грузия 2026» rate=0.030427
```

`state=` — текущее состояние FSM. Если сообщение пришло (`ВХОД | message`), а ответа нет (`ОТВЕТ` отсутствует) — хендлер не выбран или упал; трейсбек будет в `bot_errors.log`.

## 🐛 Диагностика: кнопки не нажимаются

Самый неочевидный случай, с которым реально столкнулись: **текстовые сообщения работают, а inline-кнопки молча не отвечают**.

Причина — `allowed_updates`. Telegram запоминает последнюю заданную настройку и при `allowed_updates=None` продолжает применять **старую**. Если в прошлый раз в ней не было `callback_query`, сервер отбрасывает эти апдейты ещё до доставки боту — в логе не будет ни строки `ВХОД | callback`.

Проверка:

```
https://api.telegram.org/bot<ТОКЕН>/getWebhookInfo
```

Поле `allowed_updates` должно содержать `callback_query`. В `main.py` список передаётся явно и неизменно:

```python
ALLOWED_UPDATES = ["message", "edited_message", "callback_query", "inline_query"]
```

Прочие причины «ничего не происходит»:

- **Нажатие на кнопки из старых сообщений.** FSM хранится в памяти процесса и сбрасывается при перезапуске. После рестарта отправьте `/start` и начните сценарий заново.
- **Второй экземпляр бота.** Telegram отдаёт каждый апдейт только одному потребителю `getUpdates` — второй процесс «крадёт» обновления. В `bot.log` будет две строки «Запуск бота».
- **Пустая таблица `users`.** Если `/start` не вызывался, `create_trip` падал по `FOREIGN KEY`. Сейчас регистрация выполняется внутри `create_trip`, поэтому зависимость от порядка действий устранена.

## 🔒 Безопасность

- Каждый пользователь изолирован: все запросы фильтруются по `telegram_id`
- Все SQL-запросы параметризованы (`?`-плейсхолдеры) — защита от SQL-инъекций
- `.env` добавлен в `.gitignore` и не попадает в репозиторий
- Переменные окружения валидируются при старте
